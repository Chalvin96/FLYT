# Components and interaction

Shared UI components own reusable primitives; pages own composition and domain copy. Preserve focus return, keyboard disclosure, accessible names, live announcements, and noninteractive loading skeletons. One transition must not be announced by both its visible status and a visually hidden live region.

Use direct, mature action/status copy. Distinguish loading, retryable failure, unavailable evaluation, success, and unknown destructive outcomes. Lesson and review render the same operation components; audio cleanup, write drafts, and retry state stay with those components. Reading and extension translation keep source tokens interactive for lookup.
Long lexicon headwords wrap responsively. Structured expression forms use the
verified natural primary phrase for both visible and accessible headings, with
complete alternatives under `Other forms`; legacy rows fall back to the
canonical display formatter.

The shared lemma header has a flashcard presentation that places POS and grammar
chips above the heading and keeps available IPA, tone, and audio together beside
or beneath it as width allows. The shared pronunciation row can place audio after
the metadata, while its default placement remains unchanged for other consumers.
The quiet compact audio appearance changes only the visible control; its 44px
hit area, accessible play/playing/retry labels, and playback cleanup remain the
shared audio button's contract.
