One open sub-decision — the pending vs processing distinction. R-002 lists both as separate states. Pick how visible that split should be:

A

One "Processing…" treatment (recommended)

pending + processing look identical to the learner (busy card above). Status enum still tracks both under the hood; the user only cares "not ready yet." Simplest, least flicker.

B

Distinct "Queued" vs "Processing…"

pending shows "Queued", processing shows "Processing…". Honest about queue waits under load, but two near-identical states add copy + transitions the learner rarely benefits from at MVP scale.
